# ownlanding

[Открыть сайт](https://ownlanding.vercel.app) · [Админка](https://ownlanding.vercel.app/admin)

Персональная страница со ссылками и русской админкой на Next.js и Payload CMS.

В админке можно менять имя, описание, подпись, кнопки, соцсети, иконки, цвета, шрифты, аватарку и фон. Есть загрузка своих фотографий, медиатека, черновики и предпросмотр перед публикацией.

## Запуск на компьютере

Нужен Node.js 22 LTS, версия 22.13 или новее в ветке 22.x.

```bash
npm ci
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Вставьте сгенерированную строку в `PAYLOAD_SECRET` внутри `.env`, затем:

```bash
npm run migrate
npm run dev
```

Сайт: http://127.0.0.1:3000. Админка: http://127.0.0.1:3000/admin.
При первом запуске создайте собственную учётную запись администратора.

В новый экземпляр импортируется опубликованный профиль из `src/data/published-site.json` вместе с выбранными фотографиями. Пароли, пользователи, черновики и исходная база в репозиторий не входят.

## Сохранение изменений для переноса

Сначала нажмите «Опубликовать изменения» в локальной админке. При работающем локальном сервере выполните:

```bash
npm run export:content
```

Команда обновляет снимок опубликованного контента и копирует только используемые аватарку и фон в `public/assets/profile/`. Изменения можно проверить и сохранить в Git. Снимок используется только при создании пустой базы; существующую базу он не перезаписывает.

## Размещение в интернете

Для работы **сайта и админки** нужен Node.js-хостинг, постоянная база данных и постоянное хранилище фотографий. GitHub Pages запускает только статические сайты и для Payload не подходит.

Бесплатный вариант для личного некоммерческого проекта: Vercel Hobby, Turso Free для базы и Vercel Blob Hobby для фотографий. У сервисов есть лимиты бесплатных тарифов. В облаке проект использует Turso через libSQL и прямую загрузку фотографий в Vercel Blob; ограничение фотографии — 10 МБ. Локальные SQLite и папка `media/` сохраняются для разработки.

1. Создайте базу Turso и публичное хранилище Vercel Blob. Сохраните их URL и токены в приватном `.env` вместе с `PAYLOAD_SECRET`.
2. Для облачной базы задайте `DATABASE_URI=libsql://…`, `DATABASE_AUTH_TOKEN` и `BLOB_READ_WRITE_TOKEN`. Добавьте только для первоначальной настройки `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD` (не короче 12 символов), `BOOTSTRAP_ADMIN_NAME`.
Интеграция Turso в Vercel автоматически задает `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`: проект поддерживает эти имена, они имеют приоритет над `DATABASE_URI` и `DATABASE_AUTH_TOKEN`. Для приватной настройки можно сохранить облачные переменные в `.env.cloud`; команда bootstrap прочитает его после `.env`.

3. До публичного развертывания выполните `npm run bootstrap:cloud`. Команда применит миграции, создаст администратора и перенесет опубликованный профиль с фотографиями. Повторный запуск не перезаписывает пароль и существующий контент.
4. Импортируйте репозиторий в Vercel как Next.js-проект. В настройках Production задайте `PAYLOAD_SECRET`, `DATABASE_URI`, `DATABASE_AUTH_TOKEN`, `BLOB_READ_WRITE_TOKEN`, `NEXT_PUBLIC_SERVER_URL` с публичным HTTPS-адресом. Переменные `BOOTSTRAP_ADMIN_*` в Vercel не нужны. Запустите Deploy.
5. Откройте `/admin` и войдите созданной учетной записью. После «Опубликовать изменения» обновления сразу видны на публичном сайте.

Облачная публичная регистрация первого администратора отключена: учетная запись создается только приватной командой. Миграции при будущих обновлениях запускайте отдельно через `npm run migrate` с переменными облачной базы перед развертыванием. Для Preview используйте отдельную базу и Blob-хранилище; не подключайте непроверенные ветки к Production.

Если нужен запуск локального сайта после облачной настройки, верните `DATABASE_URI=file:./data/payload.db` и очистите `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `DATABASE_AUTH_TOKEN` и `BLOB_READ_WRITE_TOKEN` в локальном `.env`.
